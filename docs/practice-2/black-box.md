# Чёрный ящик: классы, границы и правило принятия ответа

Ожидания основаны на разделах 1.5, 4.5, 5.3–5.4 и 6.3 первой работы:
параметры теста ограничены, ответ принимает только владелец активной попытки на
текущий вопрос, один из четырёх индексов. Принятый последний ответ завершает попытку.
Эта спецификация задана до обращения к внутренним деталям ветвей.

## Параметры теста — уровень формы TestForm

| Вход | Валидный класс | Невалидные классы | Проверенные границы |
|---|---|---|---|
| initial | Целые 1–5 | ≤0, ≥6, нецелый текст, пустой, отсутствующий | **0, 1, 2, 4, 5, 6** |
| length | Целые 1–100 | ≤0, ≥101, нецелый текст, пустой, отсутствующий | **0, 1, 2, 99, 100, 101** |
| Тип/пропуск обоих полей | HTML-целое | `abc`, `1.5`, `''`, ключ отсутствует | Каждый пример для каждого поля |
| Вопросы и тема | Все вопросы выбранной темы | Иная тема, недостаточный банк при публикации | Прежний test_test_validation_rejects_foreign_topic_and_insufficient_bank |

Границы длины проверяются на **неопубликованном** тесте: длина 99/100 допустима
как настройка черновика независимо от размера доступного банка. Это отделяет
валидацию числового диапазона от условия публикации. Форма в тестах не сохраняется;
число TestDefinition после невалидного ввода не изменилось. Проверка формы не
является прямой проверкой произвольных ORM-записей.

`test_form_boundaries_types_missing` выполняет все строки, включая min−1/min/min+1/
max−1/max/max+1. Факты — `black-box-results.csv` и `results/test-evidence.json`.

## Допустимость ответа — предметный сервис + HTTP

| Вход | Валидные классы | Невалидные классы | Уровень |
|---|---|---|---|
| Вариант | Целые индексы 0,1,2,3 | −1,4 | Сервис `answer` |
| Вариант | HTML-строка целого индекса | `abc`, `1.0`, пустой, пропущенный, −1,4 | POST `/attempts/<id>/` |
| question | Идентификатор текущего снимка | Старый/иной вопрос; `abc`, пустой, пропущенный | Сервис; неверные типы — HTTP |
| attempt/student | Существующая собственная попытка | Чужая, несуществующая | Сервис; чужая также старый HTTP-тест |
| Состояние | IN_PROGRESS | COMPLETED, ABORTED | Сервис |

Для индекса 0–3 набор BVA: **−1,0,1,2,3,4**. Отсутствующий вариант по HTTP
превращается в недопустимый −1; нечисловой ввод обрабатывается представлением.
Ожидается redirect (302), сообщение об ошибке и отсутствие изменений, а не HTTP 400:
приложение имеет интерфейс HTML-форм, не JSON API.
Для завершённой попытки представление перенаправляет на результат; запрет записи
дополнительно проверен прямо в сервисе. Произвольные объекты Python, float и bool
не объявляются поддерживаемыми входами сервисного API; проверка неверных типов
проводится на пользовательской HTTP-границе.

## Причины и следствия

Обозначения:

* C1 — попытка существует и принадлежит отправителю.
* C2 — состояние IN_PROGRESS.
* C3 — идентификатор вопроса равен текущему снимку.
* C4 — выбран допустимый индекс.
* C5 — отвечаемый шаг последний (step ≥ length).
* A — допустимая отправка: C1 AND C2 AND C3 AND C4.
* Reject — NOT C1 OR NOT C2 OR NOT C3 OR NOT C4.
* Finish — A AND C5; Next — A AND NOT C5.

Диаграмма: `diagrams/answer-causes.dot` и SVG. Завершение, назначение и отклонение
рассматриваются при исправных зависимостях; отказ ORM/движка отдельно ведёт к
откату и проверен интеграционными тестами. Признак правильности влияет на целевой
уровень после принятия, но не является причиной допустимости отправки.

### Ограничения E, I, O, R, M

Используется следующая явная интерпретация обозначений из задания.

| Символ | Смысл | Применение |
|---|---|---|
| E | Не более одного из группы | Состояния ACTIVE/COMPLETED/ABORTED взаимоисключающие; также пара Finish/Next |
| I | Хотя бы одно из группы | Для существующей корректной попытки есть хотя бы одно из трёх состояний; избыточно при O |
| O | Ровно одно из группы | Состояние попытки; при исправных зависимостях ровно один итог Reject/Finish/Next |
| R | Требование другого условия | Finish требует A и C5; Next требует A и NOT C5 |
| M | Маскирование следствия другим | Reject маскирует Finish и Next; их действий не должно быть |

Ограничения состояний описывают предметную область, не дополнительную валидацию
произвольных строк БД. Между C1–C4 **нет** ограничения E/O: несколько причин могут
быть одновременно истинными или ложными. I для них тоже неприменимо: все четыре
могут быть ложными у недопустимого запроса. При отказе БД ограничение O на три
бизнес-итога не применяется: появляется отдельный технический исход «откат».
M — требование отсутствия действий, а не выполнение исключённой ветви.

Во всех отказах сравниваются revision, current_id, state, finished, все назначения
снимков (step/target/reason/shown) и список ответов до/после. Проверка ошибок в пяти
точках записи подтверждает отсутствие частично сохранённого Answer или нового шага.

Полного перебора всех совместных некорректных причин не выполнялось: применяется
сжатая таблица с поочерёдным нарушением каждой существенной причины.
