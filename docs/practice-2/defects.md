# Карточки отладки

Обнаружен один реальный недостаток обработки ошибки, ещё два дефекта внесены
учебно согласно PDF. Потенциальные риски не объявляются обнаруженными дефектами.
Тестирование нормальных входов и исходных 34 сценариев не выявило иных сбоев.

## Изоляция и воспроизведение

```powershell
.\.venv\Scripts\python -X utf8 tools/practice2_defects.py
```

Скрипт запускает шесть дочерних процессов: для каждого дефекта один и тот же тест
с дефектом и без него. Текст модуля подменяется через compile/exec **только в памяти
процесса**, до импорта теста. В production-файлы скрипт не пишет. Django использует
отдельную in-memory БД. SHA-256 domain/services до и после совпадают
(`results/defects.json`, `source_unchanged=true`). В итоговом коде нет переключателей
учебных дефектов; патчи в `defects/` предназначены только для изучения.

В каждом процессе реально включается `sys.settrace`; строки `TRACE` содержат
номер и фактический текст строки, событие line/return/exception и ограниченный
набор локальных значений на синтетических данных. Это использованный инструмент
локализации, а не рекомендация воспользоваться отладчиком позднее.
Переданные пользователем секреты и реальные записи БД в трассы не попадают.

## D1 — граничный, учебный

* Происхождение: искусственная замена `max(1, min(5, ...))` на `max(2, min(5, ...))`.
* Симптом: неверный ответ на вопрос сложности 1 даёт цель 2.
* Вход: `actual=1`, `correct=False`.
* Ожидается: 1. С дефектом: 2, `AssertionError: 2 != 1`.
* Падающий тест: `testing.test_practice2.WhiteBoxTests.test_strategy_paths_and_clamps`.
* Локализация: `results/D1-before.txt`, TRACE next_target показывает actual=1,
  correct=false и изменённую строку clamp. Там же фактическое падение assertion.
* Root cause: неверная нижняя константа насыщения, не ошибка расчёта шага.
* Исправление: нижний предел 1. Исходный корректный модуль исполняется в контрольном
  процессе без учебной подмены.
* После: тот же тест PASS (`D1-after.txt`); дополнительно полная регрессия 51 тест.
* Воспроизводимый diff: `defects/D1-educational.patch`.

Отдельный запуск только дефектной версии (ожидаемый exit 1):

```powershell
.\.venv\Scripts\python -X utf8 tools/practice2_defects.py --child D1 --mutated
```

Без `--mutated` ожидается exit 0. Общий скрипт проверяет оба кода автоматически.

## D2 — интеграция сервиса и хранилища, реальный обработчик

* Происхождение: имевшийся в исходном services.py обработчик любого IntegrityError
  безусловно выполнял `Attempt.objects.get(... state='IN_PROGRESS')`.
* Условие воспроизведения: ошибка целостности при создании снимков, при которой
  нет другой активной попытки. На обычном банке такая ошибка не наблюдалась.
  Использована **контролируемая инъекция отказа зависимости**: тест сначала
  записывает реальные снимки, затем пытается вставить повторный source_id.
  SQLite действительно возбуждает UNIQUE constraint failed, а не заранее
  подставленный текст ошибки. Дефектный обработчик не вносился в исходную версию.
* Симптом: после отката вылетает `Attempt.DoesNotExist`; верхнее HTTP-представление
  обрабатывает ScenarioError, поэтому такая ошибка могла бы превратиться в 500.
  Реальный браузерный 500 не запускался; проверено исключение сервисного слоя.
* Ожидается: контролируемый ScenarioError с исходным IntegrityError в `__cause__`;
  ни Attempt, ни AttemptQuestion не должны остаться.
* Факт до: `FAILED (errors=1)`, цепочка UNIQUE → IntegrityError → DoesNotExist
  в `results/D2-discovery.txt`. Откат работал уже до исправления; дефект относится
  к передаче ошибки через границу модулей, а не к потере атомарности.
* Тест: `testing.test_practice2.IntegrationTests.test_start_integrity_failure_reports_scenario_and_rolls_back`.
* Локализация: исходный traceback указал except/get в start; дополнительный
  `sys.settrace` в `D2-before.txt` показывает вход в обработчик после сбоя вставки
  и исключение в `.get`. Тест вызывает фактическое ограничение snapshot_source.
* Root cause: смешаны два случая — конкурентное создание активной попытки и
  иное нарушение целостности. Наличие IntegrityError не доказывает существование
  конкурирующей записи.
* Исправление: поиск через filter.first; если активная запись найдена, она
  возвращается, иначе возбуждается ScenarioError `from exc`.
* После: **тот же тест** PASS в `D2-fixed.txt` и `D2-after.txt`; отдельно проверены
  восстановление конкурирующей попытки (stub) и OperationalError. Финальная
  регрессия включает реальные конкурентные ответы из прежних тестов.
* Diff для безопасного воспроизведения старого обработчика на итоговом коде:
  `defects/D2-real.patch`. Он возвращает исходную ошибку в памяти процесса,
  а не объявляет её искусственным дефектом.

```powershell
.\.venv\Scripts\python -X utf8 tools/practice2_defects.py --child D2 --mutated
.\.venv\Scripts\python manage.py test testing.test_practice2.IntegrationTests.test_start_integrity_failure_reports_scenario_and_rolls_back --verbosity 2
```

Первая команда ожидаемо завершается 1, вторая — 0. Инъекция повторного source_id
является тестовым стимулом. Она не означает, что valid_bank в нормальной работе
возвращает дубликаты, и не считается вторым найденным дефектом.

## D3 — логика состояния, учебный

* Происхождение: искусственная замена `q.step >= a.length` на `q.step > a.length`.
* Симптом: после трёх ответов при length=3 попытка остаётся IN_PROGRESS,
  назначается четвёртый вопрос из достаточно большого банка.
* Ожидается: COMPLETED, finished заполнен, current=None, ровно три ответа.
* Факт с дефектом: `AssertionError: 'IN_PROGRESS' != 'COMPLETED'`.
* Падающий тест: существующий
  `testing.tests.ScenarioTests.test_complete_and_no_repeated_questions`.
* Локализация: `results/D3-before.txt`, TRACE answer на третьем ответе показывает
  q.step=3, a.length=3 и переход в `_choose` вместо завершения.
* Root cause: ошибка строгого сравнения на границе состояния завершения.
* Исправление: восстановить >=. Тот же тест PASS в `D3-after.txt`.
* Регрессия: прежние тесты запрета ответа после завершения, повторов и новый
  сценарий length=1; полный итоговый запуск.
* Diff: `defects/D3-educational.patch`.

```powershell
.\.venv\Scripts\python -X utf8 tools/practice2_defects.py --child D3 --mutated
```
